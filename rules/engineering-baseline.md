# Engineering Baseline

- Read the relevant project files before making implementation decisions.
- Prefer existing project patterns, scripts, helpers, and naming conventions.
- Keep changes scoped to the user request and the affected behavior.
- Preserve user work in a dirty working tree; never revert unrelated changes.
- Avoid adding abstractions unless they remove real complexity or match local style.
- When requirements are ambiguous, clarify the smallest necessary point or state the assumption.
