# Subagents

这个文件夹存放可复用的 subagent 角色定义和调用说明。

Subagent 适合处理边界清晰、可并行、可独立验证的任务，例如：

- 只读探索代码结构。
- 专门跑测试和分析失败日志。
- 专门做安全/密钥检查。
- 专门做 UI 截图 review。
- 在独立工作区尝试某个方案。

## 建议结构

每个 subagent 用一个独立目录包装，入口文件统一叫 `SUBAGENT.md`：

```text
subagents/
  子代理名称/
    SUBAGENT.md
```

## Subagent 索引

| Subagent | 用途 |
|----------|------|
| [`代码探索/`](./代码探索/SUBAGENT.md) | 只读探索项目结构、关键入口、约定和风险。 |
| [`测试执行/`](./测试执行/SUBAGENT.md) | 运行测试、整理失败日志、给出最小复现线索。 |
| [`视觉审查/`](./视觉审查/SUBAGENT.md) | 生成并 review UI/Webview 截图。 |
| [`密钥检查/`](./密钥检查/SUBAGENT.md) | 检查待提交内容是否包含密钥或敏感信息。 |

## 编写原则

- 说明这个 subagent 适合什么时候用。
- 明确是否只读、是否允许执行命令、是否允许改文件。
- 明确最终必须返回哪些信息。
- 不要把完整用户任务直接丢给 subagent；主 agent 要负责整合结果和最终决策。
- 涉及多个独立方向时，优先并行启动多个 subagent。
